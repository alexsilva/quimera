# Change Log

## Unreleased
- fix(runtime): se `exec_command` falhar depois de registrar a sessão, mas antes de devolver o `session_id` (por exemplo ao iniciar as threads leitoras), a sessão é removida e o processo encerrado para não ficar órfão e inacessível ao agente. Regressão em `tests/test_runtime_tools_shell.py`.
- fix(runtime): ao passar de 64 sessões do `exec_command`, a mais antiga era morta em silêncio, mesmo em execução, e a checagem só acontecia depois do spawn. A vaga passa a ser reservada sob lock antes de iniciar o processo. Com a capacidade cheia, a sessão encerrada e ociosa mais antiga é liberada, pois uma sessão que terminou sem ninguém consultá-la não tem como ser fechada (não há limpeza periódica nem tool para listar sessões, e o limite é compartilhado por todos os agentes da sessão MCP). Sessões em execução nunca são descartadas, e as que uma tool está lendo (`write_stdin`, `poll_command_session`, `close_command_session` ou a coleta do próprio `exec_command`, marcadas por `CommandSession.in_use`) também não. A recusa só ocorre com todas as vagas em execução ou em uso e lista os ids e comandos abertos para o agente fechar com `close_command_session`. Também: o resultado `completed` e o `close_command_session` esperam as threads leitoras (até 0,5 s) antes de montar a saída, em vez de perder o fim de stdout/stderr ainda nos pipes; falha do `Popen` após `pty.openpty` fecha os dois descritores; a limpeza fecha stdin/stdout/stderr quando não há leitora viva. Regressões em `tests/test_runtime_tools_shell.py`.
- fix(mcp): falha de tool sem `error` preenchido chegava ao cliente MCP só como `Tool execution failed`. É o caso do `run_shell` com exit code diferente de zero: stderr e exit code ficam em `content`, que não entrava no texto, e o agente via a falha sem o motivo. O texto passa a juntar `error` e `content` sem repetir trechos iguais, e `structuredContent.error` vai como string (o `ToolError` cru não é serializável em JSON). Regressões em `tests/test_runtime_mcp_server.py` e `tests/test_mcp_http_server.py`.
- fix(tui): o editor do MCP Hub abria o campo Ambiente sempre vazio, mesmo com variáveis persistidas para a conexão (a dica dizia `vazio mantém o existente`): não havia como conferir o que estava salvo, digitar uma variável nova substituía o conjunto inteiro e renomear a conexão descartava o ambiente. O campo passa a nascer com os pares `KEY=valor` gravados em `mcp-connections.json`; ao salvar, o que está no campo é o que fica persistido (vazio remove) e o ambiente acompanha a conexão renomeada. Partes sem `KEY=` são rejeitadas antes de gravar, em vez de descartadas em silêncio pelo parser. `MCPConnectionManager.env_spec_for` vira `env_text_for`. Regressões em `tests/test_textual_ui.py` e `tests/test_mcp_client_bridge.py`.
- refactor(mcp): separa os dois sentidos de conexão em arquivos inequívocos. Servidores externos usados pelo Quimera ficam em `<workspace>/mcp-connections.json`; o estado de clientes autorizados no servidor HTTP do Quimera fica em `<base_dir>/state/mcp-server.json`. `config.json` permanece exclusivo das opções gerais do workspace. Não há fallback para os nomes anteriores. O MCP Hub lê as autorizações válidas do novo store em modo somente leitura quando a sessão está sem `--mcp-http`, evitando que a aba Clientes pareça ter perdido dados; revogação continua disponível apenas com o servidor ativo.
- fix(mcp): lotes JSON-RPC deixam de capturar e descartar respostas standalone pendentes na mesma conexão. Cada batch recebe identidade própria, o flusher ignora somente as calls pertencentes ao agregador e, no stdio, apenas a espera pelo lote vai para background; o reader continua livre para processar `notifications/cancelled`. Erros imediatos de validação de `tools/call` também voltam no array do batch. Resultados de tool sem evento de início (como `argument_error`) passam a criar evidência correlacionada pelo `tool_call_id`, que também segue no payload de atividade. Cancelar uma call ainda na fila do pool impede sua execução (uma mutação enfileirada não roda depois do cancel); o agregador do batch respeita o deadline de cada tool (o orçamento de `delegate` não é cortado pelo timeout genérico) e libera as demais respostas sem esperar uma tool cancelada que ignore o evento. Regressões em `test_mcp_async_events.py` e `test_agents.py`.
- feat(runtime): tool calls independentes passam a executar em paralelo também no harness nativo compartilhado por OpenAI-compatible, Codex Cloud e Claude Cloud. O modelo já podia devolver várias calls no mesmo turno (Codex Cloud anuncia `parallel_tool_calls=true`), mas o runtime as percorria num `for` serial. Runs adjacentes explicitamente `parallel_safe` nos metadados canônicos — arquivos/search/tasks/memória/host/git somente leitura — usam agora um pool limitado por `ToolRuntimeConfig.max_parallel_tool_calls` (padrão 4); mutações, shell, `ask_user`, delegação, browser state, tools MCP externas e calls que abririam approval continuam como barreiras seriais. Cancelamento e escopo de aprovação são copiados para cada worker, progresso deixa de usar um slot global sujeito a corrida, callbacks de conclusão refletem a ordem real e o histórico enviado ao modelo preserva a ordem original. A UI correlaciona calls iguais por `tool_call_id`, que passa a fazer parte do contrato dos callbacks `on_tool_call`. O servidor MCP tem pool próprio, dimensionado por `ToolRuntimeConfig.mcp_tool_pool_workers` (padrão 4) e compartilhado por todos os agentes da sessão; `delegate` aguarda o agente filho em um pool separado, para não ocupar os workers de que as tools do filho precisam. `tools/list` passa a publicar `readOnlyHint`, `destructiveHint` e `openWorldHint` (hints apenas; enforcement segue em policy/approval). Regressões em `test_openai_compat_driver.py`, `test_runtime_executor.py`, `test_tool_metadata.py`, `test_runtime_mcp_server.py`, `test_mcp_async_events.py` e `test_agents.py`.
- fix(app): o chat deixa de ecoar registros de log. O handler de tela do logger `quimera.staging` (`PromptAwareStderrHandler`) reencaminhava todo WARNING/ERROR ao feed como linha de sistema (`agent_gateway: falha no backend agent=…`, `chat_processor: …`), duplicando avisos que o app já emite explicitamente e poluindo o chat a cada falha de backend. A política desde `949704f` é: log técnico vai para o arquivo e o chat só recebe notificações explícitas; o handler agora cumpre isso e só retém WARNING+ emitidos antes de a UI subir, para o `drain_to_stderr` pós-saída. Também sai o aviso `<agente> foi removido após falhas repetidas` do `AgentFailureTracker`; a remoção fica registrada no log da aplicação em WARNING. A linha `[bug …] agent_failure_burst` continua no chat. Saem `AppCallbacks`, `bind_callbacks`, `_friendly_message` e o ramo morto de logs do servidor MCP em debug (o logger do MCP é só-arquivo desde `840bc72`). Testes em `tests/test_app_handlers.py`, `tests/test_quimera_protocol.py` e `tests/test_bugs.py`.
- fix(tui): a linha de stats de ferramentas (`N ferramentas · N concluídas · …`) aparecia acima da resposta final do agente, ou sozinha, sem resposta alguma. O feed guardava o resumo pendente pela chave de execução e, se essa chave já constasse como finalizada, o anexava como item avulso. Mas os eventos transitórios do turno saem com `run_id` enquanto o `turn_summary` e a `agent_message` saem sem (o contexto de run é limpo em `clear_agent_transient`, antes deles): a chave base ficava finalizada desde a primeira resposta do agente e todo resumo seguinte caía no caminho avulso — antes da resposta no chat, ou órfão em delegações com `show_output=False`, cuja resposta não entra no feed. O resumo passa a ficar pendente pelo agente base, existe só como rodapé da resposta final e é descartado quando uma nova execução do mesmo agente começa (`stream_start`, `agent_update` ou lifecycle RUNNING) sem a resposta ter chegado. Vale para todos os perfis (API, CLI, cloud, delegações). Regressões em `tests/test_textual_ui.py`.
- fix(tui): linhas do feed e de telas modais (paleta de comandos/temas) apareciam deslocadas uma célula à esquerda — borda e scrollbar "quebradas" — sempre que a linha continha um emoji. Causa: o Textual reserva as células que o Rich mede (tabela Unicode mais recente: todo emoji vale 2; símbolo estreito + U+FE0F, como os ícones `☁️`/`⚙️`, vale 2) e numa repintura completa escreve cada linha de uma vez posicionando o cursor só no início; terminais com outra tabela (xterm.js sem o addon `unicode11`, caso da TinyIDE, dá 1 célula a `🤖`, `🪐`, `⚡`) ou que ignoram o seletor (VTE, xterm.js) consomem menos células e tudo após o símbolo escorrega. Novo driver `quimera/ui/textual/driver.py` (`QuimeraLinuxDriver`, instalado via `App(driver_class=...)`): na partida, antes do primeiro frame, mede no próprio terminal quantas células cada sonda ocupa (`CSI 6 n`, resposta via `events.CursorPosition` do parser do Textual). `quimera/ui/textual/cell_widths.py` traduz as medidas na tabela do Rich que reproduz o terminal, ativada por `UNICODE_VERSION` (uma já definida é respeitada; a variável é herdada pelos agentes filhos), e materializa o U+FE0F como espaço na saída quando o terminal o ignora (terminais que o honram mantêm o emoji colorido). Sem resposta em 1 s nada muda. Como a variável chega aos processos filhos, `tests/conftest.py` a remove para a suíte medir com a tabela padrão do Rich (os baselines visuais pressupõem isso). Testes em `tests/test_textual_cell_widths.py` e, com o `LinuxDriver` real num pseudo-terminal, `tests/test_textual_driver.py`. O recorte do glifo em terminais que reservam 1 célula para emoji continua sendo do terminal.
- fix(mcp): servidores MCP externos via `stdio`/`remote` (ex.: `mcp-remote` da TinyIDE, GitHub, Jira) morriam logo após `conectado`. O `bwrap --die-with-parent` (`PR_SET_PDEATHSIG`) amarra o processo à *thread* que o criou, e o handshake roda em threads curtas (boot em background e MCP Hub): ao fim da thread o proxy recebia SIGKILL, a sessão seguia viva com o pipe quebrado (`Broken pipe` em `tools/list`, tools sumindo do registry, `Unknown tool`/falha em toda `tools/call`). O `Popen` do transporte stdio passa a rodar numa thread que drena o stderr e vive enquanto o processo viver, preservando o die-with-parent no encerramento do app. Regressão em `tests/test_mcp_client_bridge.py`.
- fix(prompt): `<evidence_context>` (já definido em `prompt.md` e `delegate_prompt.md`) passa a ser carregado e renderizado somente quando `PromptBuilder.build(debug=True)`; fora do debug o store de evidências nem é consultado.
- fix(prompt): o bloco `<session_state>` (sessão, job, workspace raiz, diretório atual e SO) passa a ser renderizado para os kinds `DELEGATION`, `TASK_EXECUTOR` e `TASK_REVIEWER` mesmo com `primary=False`. A tool `delegate`, o debate e os runners de task sempre chamam com `primary=False`, então o bloco previsto em `delegate_prompt.md` e `task_prompt.md` nunca chegava ao agente. O chat humano mantém a economia para falantes secundários.
- refactor(prompt): delegação agente→agente deixa de reutilizar o prompt do chat humano. Novo `PromptKind.DELEGATION` com template próprio `quimera/delegate_prompt.md` (identificação do agente e do solicitante, protocolo de delegação, payload com `role`/`access_list`, instrução detalhada opcional), usado pela tool `delegate` e pelo debate. `prompt.md` volta a ser exclusivo da conversa com o humano: saem o bloco `<delegation>` e as regras de `delegation_only`. Adapter OpenAI-compat ganha o mapa de roles do novo kind; servidor MCP expõe `quimera://prompts/delegation`.
- feat(metrics): métricas de comportamento deixam de ser injetadas no prompt (bloco `<agent_metrics>` removido de `prompt.md`) e passam a ser dados de entrega estáticos consultáveis pelo humano via `/stats` (`/stats`, `/stats <agente>`, `/stats json [<agente>]`). A coleta e a persistência em `<workspace>/state/metrics_state.json` seguem inalteradas. Novos `quimera/metrics_report.py` (`AgentStatsReporter`) e `quimera/app/stats_services.py` (`StatsServices`); `PromptBuilder` não recebe mais `metrics_tracker`.
- feat(metrics): nova ação `/stats reset [<agente>]` zera as métricas acumuladas de um agente ou de todos, persistindo a limpeza em `<workspace>/state/metrics_state.json` (`BehaviorMetricsTracker.reset_agent`/`reset_all`, `AgentStatsReporter.render_reset`).
- fix(app): exception dentro de um handler de comando slash deixa de derrubar o chat. `run_chat_loop` passa por `_handle_command_safely`, que registra o traceback, exibe um aviso no feed e consome a entrada em vez de propagar a falha.
- refactor(metrics): remove a camada de feedback/diagnóstico das métricas. `BehaviorMetricsTracker.generate_feedback`, `get_position_summary` e `collect_warnings` foram eliminados, junto com a ação `/stats feedback` e as linhas de "atenção" dos relatórios. Só restam dados de entrega dos agentes.
- fix(mcp): estado do servidor (`mcp-server.json`) passa a ser global do app em `<base_dir>/state/` (ex.: `~/.local/share/quimera/state/`), em vez de por workspace. Clients externos e refresh tokens sobrevivem à troca de workspace sem reautorização.
- feat(mcp): Authorization Server OAuth 2.1 completo embutido no servidor MCP HTTP (`quimera/runtime/mcp/oauth.py`). Implementa `authorization_code` com PKCE `S256` obrigatório, `refresh_token` rotativo, `client_credentials`, Dynamic Client Registration (RFC 7591), revogação (RFC 7009), introspecção (RFC 7662), metadados de AS (RFC 8414) e de recurso protegido (RFC 9728), audience binding por `resource` (RFC 8707) e redirect loopback de porta efêmera (RFC 8252). Configuração em uma flag (`--mcp-oauth`): o client MCP descobre, registra-se e autoriza sem intervenção manual. O esquema de token estático em header (`Authorization: Bearer` / `X-Quimera-MCP-Token`) continua válido em paralelo — nenhuma quebra para clientes existentes. Escopos `mcp:read-local|read|agent|all` podem restringir (nunca ampliar) o perfil de tools do transporte, refletindo em `tools/list` e `tools/call`. Clients dinâmicos e refresh tokens persistem em `<base_dir>/state/mcp-server.json` (`0600`). Metadados respeitam `X-Forwarded-Proto`/`X-Forwarded-Host` para operação atrás de túnel. Tela de consentimento HTML autocontida com passcode opcional, `X-Frame-Options: DENY` e `Referrer-Policy: no-referrer`. 48 testes ponta a ponta em `tests/test_mcp_oauth.py`.
- feat(mcp): criptografia opcional do store OAuth via `QUIMERA_MCP_OAUTH_STORE_KEY` (Fernet + PBKDF2; extra `oauth-store` / `cryptography`). Sem a chave o JSON continua em texto claro com permissões `0600` — documentado em `docs/guia/mcp-e-ferramentas.md` e `docs/referencia/dependencias.md`.
- build: versão do aplicativo derivada automaticamente de tags e commits Git
  via `setuptools-scm`, compartilhada pelo CLI, banner e servidor MCP.
- fix(runtime): estabiliza delegação entre agentes CLI. Toda delegação originada de tool call (socket interno ou HTTP) passa a usar `AgentClient` isolado criado por chamada, eliminando reentrância de `AgentClient.run()` sobre o client principal do chat (que corrompia `cancel_event`, `_current_proc` e parava o EscMonitor do agente origem). O client de background herda `pause_idle_if` (delegado aguardando tool longa não morre por idle timeout) e `process_supervisor` (subprocessos delegados entram no `terminate_all()`). ESC/Ctrl+C propaga aos clients de background via `add_cancel_listener` → `TaskExecutorPool.cancel_background_work()`. Guard de reentrância com log de erro em `AgentClient.run()`. Testes em `test_agents.py`, `test_bootstrap_wiring.py`, `test_delegate_http_async.py` e `test_task_execution_service.py`.
- feat(runtime): ferramentas de automação de navegador (`browser_*`, Chrome/Chromium via Playwright, extra `browser`); screenshots salvos por sessão no diretório de artefatos do workspace, com leitura permitida [47465fe, 008ca71].
- feat(runtime): política de workspace de desenvolvedor (`workspace_policy`) [452a8ef].
- docs: README, ARCHITECTURE e guia MCP atualizados para o conjunto atual de 49 tools (git, browser, memória, símbolos, interação) e para o novo fluxo de delegação isolada.
- API Public: Stabilize QuimeraApp public surface. Expose only essential interfaces via quimera.app.__init__: QuimeraApp, logger, and PromptAwareStderrHandler. No breaking changes expected relative to previous public interface (item 5).
- Compatibility: API surface reviewed; public surface remains stable with no breaking changes anticipated.
- Document any future breaking changes here to aid consumers.
